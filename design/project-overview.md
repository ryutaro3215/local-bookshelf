# プロジェクト概要（デザイン作成用）

> このドキュメントは、デザイン作成のAI・デザイナーにプロジェクトの全体像を伝えるためのものです。
> 詳細な仕様の出典: `.dev/business-plan.md` / `.dev/requirements.md` / `design/share-image-research.md`（いずれも 2026-11-10 時点）
> requirements.md は現在 **draft（下書き）** で、2026-11-10 の変更はオーナーの承認待ちです。承認の結果で変わることがあります。

---

## 1. ひとことで

**スマホに自分の本棚を作る。**

表紙を撮るだけで本が登録され、本屋のように表紙がずらっと並ぶ「自分だけの本棚」をスマホの中に作り上げていくiOSアプリ。アプリ名は未定（仮称: local-bookshelf）。

## 2. 誰のためのアプリか

- 紙の本をたくさん持っていて、**どの本を持っているか・いつ何を買ったかを把握しきれていない**人
- 本を**表紙（ジャケット）で覚えている**人。書名より表紙の見た目で本を思い出す
- 本屋のように本がずらっと並んでいる光景が好きな人
- 読書記録を他人に公開したいわけではない。SNS型の読書サービス（レビュー・ランキング・タイムライン）は好まない
- ただし「自分の本棚を見せたい」という共有欲はある。BeReal のような「自分の◯◯を1枚で見せる」感覚に近い

## 3. 提供する価値

| 価値 | 内容 |
| :-- | :-- |
| 本棚を作り上げる楽しさ | 撮った表紙が棚に並び、自分の手で棚を分けて並べ替えていく過程そのものが楽しい |
| 眺める喜び | 本屋の面陳（表紙を正面に向けた陳列）のように、自分の本の表紙がずらっと並ぶ |
| 手軽さ | 登録は表紙を撮るだけ。バーコード・ISBN・情報入力は不要（題名は文字認識の候補を確かめて確定する） |
| 見せられる | 本棚や「その月・その日に買った本」を映える画像にして、Instagram や X に気軽に投稿できる |
| 安心 | 通信は一切しない。アカウント登録もない。データは自分のスマホの中だけ |

## 4. デザインの方向性（オーナーの言葉）

- **洗練されている**
- **面白みがある**
- **手軽**
- **サクサク動く**
- 本屋のように本がずらっと並んでいる感覚。それをスマホ上で「いかに作り上げていくか」が使い心地として一番大事

**このアプリの価値は、機能の数ではなく細部のデザインと作り込みにある。** 特に重要なのは次の3点です。
1. 棚を作り上げる操作の気持ちよさ（撮る → 棚に並ぶ → 並べ替える）
2. 表紙の並びの美しさ
3. 共有画像の見栄え

## 5. アプリの基本ルール（デザインの前提）

- 対応は **iPhone のみ**（iOS 26 以上）。iPad 向けの最適化はしない
- UI の言語は**日本語・英語の両対応**（端末の言語設定に従う）。初期ジャンル名・区分名・システム棚の名前も両言語で持つ（ユーザーが付けた棚の名前や題名は翻訳しない）。日付は端末の地域の書式で出す。デザインは英語の長い文言でも崩れないようにする
- 本の情報は「表紙写真＋題名（**必須**）＋ジャンル（＝棚）＋所持状況＋購入日」。このほかに、画面には出さない内部の項目「よみ」と「データ追加日」を持つ（§11）。著者・出版社・評価などの書誌情報は**持たない**
- 1冊の本は**1つのジャンル（棚）にだけ**入る（現実の本棚と同じ）
- 本はどれも「購入済み」か「買いたい」のどちらかの**所持状況**を持つ。ジャンルとは別の軸
- ジャンルの棚に並ぶのは**購入済みの本だけ**。「買いたい」の本は「**買いたい本**」に集まって表示される（§6.9）
- どのジャンルも選ばれていない本は「**未分類**」に置かれる（削除できないシステム棚）
- 登録の想定は**1人あたり最大500冊、棚は30個程度**

## 6. 画面と機能

### 6.1 本棚（閲覧画面・メイン画面）

**画面の配置**
- 上部: ボタンは置かない。**棚の名前（例「哲学・思想 ▾」）と冊数だけ**を出す
  - 棚の名前をタップすると「**棚を選ぶ**」シートが開く。区分ごとの見出しと冊数つきのリストで、すべてのジャンル（システム棚を含む）から選んで移動できる
  - 「棚を選ぶ」部品は**1種類のリスト**にそろえる。本の移動先を選ぶときも同じリストを使う（移動先を選ぶときは本が0冊のジャンルも出す）
  - 棚の位置を示す点の列（インジケータ）は置かない
- 下部バー: 左から「**表示**」・**検索欄**・「**＋**」（登録）の3つ
  - 「表示」メニューにまとめるもの: 見え方（棚／グリッド）、まとめ方（ジャンル別／購入月別）、この棚の並べ順、設定（一番下）
- 下部バーの上に、操作のヒント（← → 本をめくる　↑ ↓ 棚をかえる　棚の名前をタップで一覧）を出す

**見え方（「表示」→ 見え方）**
- **棚表示**: 本が**表紙を正面に向けて**本屋の棚のように並ぶ。横スワイプで本をめくり、縦スワイプで棚（ジャンル）を移る
  - 表紙は**元の縦横比のまま**表示する（切り抜いて揃えない）
  - 一番最後の本の次に「空きスロット」を出す。タップするとその棚を登録先にして登録を始める
- **グリッド表示**: 横3列のシンプルな一覧。縦スクロールで一覧を送り、**左右スワイプで棚を移る**

**まとめ方（「表示」→ まとめ方）**
- **ジャンル別**: 棚（ジャンル）ごとに並べる。縦スワイプの対象は、本が1冊以上入っている棚だけ（0冊の棚は出ない。登録先・移動先を選ぶときだけ出る）
- **購入月別**: 購入した月ごとに並べる
  - 横スワイプでその月の本をめくり、縦スワイプで月を移る
  - **ピンチイン**（指を閉じる）で月を年にまとめる（その年の本を横一列に並べ、縦スワイプで年を移る）。**ピンチアウト**で月に戻る。iPhone の写真アプリと同じ向き
  - 本が1冊もない月・年は飛ばす
  - 上部の月・年の名前（例「2026年10月」）には「▾」を付けない。押しても一覧は開かない
  - 並びは**購入日順で固定**。手での並べ替えはしない（「表示」メニューの「並べ順」も出さない）。本の詳細・別のジャンルへの移動・削除はできる
  - 「買いたい」の本（購入日を持たない）は出さない
  - グリッド表示も使える。月ごとの見出し（上に固定）を付けた1本の縦スクロールになる。ピンチインで年ごとの見出し＋1行5冊の細かいグリッド、ピンチアウトで月に戻る

- 本をタップすると詳細へ移る
- 本が1冊もないとき（初回起動時など）は空の画面にして、登録へ誘導する

### 6.2 撮影・登録

- 登録の入口は2つ。どちらも同じ流れ（撮影 または 写真ライブラリ → 登録待ちの一覧 → 登録）に入り、違いは最初に選ばれる棚だけ
  - A: 下部バー右端の「＋」。いつも表示する。初期の棚は直前に使った棚（なければ未分類）。本が0冊の空の画面からも同じ入口に入る
  - B: 棚表示の一番最後の本の次に出る空きスロット。その棚が登録先になる
- アプリ内のカメラで表紙を撮る。表紙の四隅を自動で検出して、まっすぐに補正する（検出できないときは手で四隅を調整する）
- **連続撮影**: カメラを閉じずに次々と撮れる。最初に何十冊・何百冊も登録する場面を想定
- 写真ライブラリにある既存の写真からも登録できる
- **登録待ちの一覧**: 本ごとに題名・ジャンルのチップ（例「哲学・思想 ▾」）・「**購入済み**」のチェックボックスを持つ
  - チェックあり＝購入済み、チェックなし＝買いたい（買いたい本に入る）
  - 初期値は**全冊チェックあり**。一覧の上部に「すべて選択」「すべて解除」を置く
  - 購入済みの本は、登録した日が購入日になる。買いたい本は購入日を持たない
- 撮った表紙が棚に並ぶまでの演出は、体験の最初の印象として重要

### 6.3 題名

- 題名は**必須**。題名が空の本は登録を確定できない
- 登録の流れの中で、端末内の文字認識で表紙から題名の**候補**を出す。ユーザーは採用・修正・破棄でき、手入力もできる
- 文字認識は撮影の邪魔をしない（裏で処理し、あとから候補が届く）
- 題名を確定すると、画面には出さない「よみ」（読みがな）が端末内で自動で作られる。題名順の並べ替えと検索に使う

### 6.4 本の詳細・編集

- 詳細は**表示だけ**: 大きな表紙、題名、ジャンル、所持状況、購入日（購入済みの本のみ）
  - データ追加日は**表示しない**
  - 買いたい本の本には「**購入した**」ボタンを出す（§6.9）
- 編集は詳細ページで行う。右上の「**編集**」で編集モードに入り、「完了」で保存、「キャンセル」で取り消す
  - 編集する項目は**所持状況にかかわらず同じ項目を同じ順で**出す: 題名・ジャンル・所持状況・購入日
  - 所持状況は「購入済み｜買いたい」の切り替えで選ぶ
  - 「買いたい」のときの購入日の行は入力できず、「購入済みにすると今日の日付が入ります」と表示する
  - 購入済みを「買いたい」に切り替えると購入日は消える（ジャンルは残る）
  - 表紙の撮り直しもここでできる
- 本の削除は、長押しで選んだあとの**下スワイプ**で確認ダイアログを出して行う

### 6.5 並べ替え（コア体験）

- 棚表示: 本を**長押しで選び**、方向で操作を分ける
  - ← → : 棚の中で位置を入れ替える
  - ↑ : 別の棚へ移動（「棚を選ぶ」リストが開く）
  - ↓ : 削除（確認ダイアログ）
- グリッド表示: 長押しでメニュー（別の棚へ移動・削除）。並べ替えは長押しからのドラッグ
- 一括の並べ順（「表示」→ この棚の並べ順）: 「手動（自分で並べた順）」「購入日（新しい順／古い順）」「データ追加日（新しい順／古い順）」「題名順」。整列したあとも手で並べ替えを続けられる
  - 題名順は「よみ」で比べる（日本語は五十音順、英語はアルファベット順）
  - データ追加日は並べ替えに使うだけで、日付そのものは画面に出さない
- 購入月別では並べ替えはできない（§6.1）

### 6.6 棚（ジャンル）の管理

- 設定画面で行う（「表示」メニューの一番下から入る）
- ジャンルの作成・名前変更・削除・並び順の変更
- ジャンルを削除すると、中の本は未分類へ移る（本は消えない）
- ユーザーが作ったジャンルは、区分「マイジャンル」に入る
- **初期ジャンル**: 書店の売り場区分をもとにした一般書向けの28件。表の順が初期の並び順

| 区分 | ジャンル |
| :-- | :-- |
| 文芸 | 小説／エッセイ／詩歌／漫画／絵本・児童書 |
| 人文 | 哲学・思想／宗教／歴史／心理／言語・語学 |
| 社会 | 政治・法律／経済・経営／ビジネス・自己啓発／社会／教育 |
| 自然科学 | 数学／物理／化学／生物／地球・宇宙 |
| 技術・医療 | コンピュータ・IT／工学・技術／医学・健康 |
| 芸術・生活 | 芸術・デザイン／音楽／料理・暮らし／旅行・地理／趣味・スポーツ |
| マイジャンル | ユーザーが作ったジャンル（例: 好きな作家の棚） |
| システム | 買いたい本／未分類（この順で末尾に固定。削除・名前変更はできない） |

### 6.7 検索

- 下部バー中央の検索欄から、全棚を横断して探す（「この本持ってたっけ？」に答える）
- **題名と「よみ」**の部分一致で探す。ひらがなとカタカナは区別しない（例:「そんざい」で『存在と時間』が出る）
- 入力に合わせて結果を絞り込み、一致した部分を強調する
- 所持状況（購入済み／買いたい）で絞り込める。絞り込みをどこに置くかはデザインで決める
- 結果が0件のときは、そのことを案内する

### 6.8 共有

- **共有の単位**は3つ
  - ジャンル別: その棚の本
  - 月別: その月に購入した本
  - 日別: その日に購入した本
  - 購入月別の画面では1日分・1か月分を、ジャンル別の画面ではその棚を共有できる
- **共有先**: Instagram のフィード、Instagram のストーリーズ、X のポスト、写真への保存
- **縦横比**（調査 `design/share-image-research.md` の推奨）
  - フィード・X・写真保存: **4:5**（1080×1350）。X で切れずに出るかは実機で確認が必要
  - ストーリーズ: **9:16**（1080×1920）。上下の端（上約14%・下約20%）は Instagram の表示が重なるので、文字やロゴを置かない
- ストーリーズへの直接投稿は Meta の仕組みを使う（Meta の開発者登録が必要）。アプリは画像を Instagram アプリへ渡すだけで、アプリ自身は通信しない。フィードと X は iPhone の共有シートから渡す
- 画像に小さくアプリ名を入れる
- 調査の方向性: まず静止画。表紙は高さをそろえて並べ、文字は日付・ジャンル名・冊数などの事実だけにする
- **共有画像（と動画）の見た目は別のタスクで設計する**。要件の「テンプレート1種類」もそこで見直す
- **共有の入口は、閲覧画面の右上の共有マーク**（2026-11-10 決定）。ジャンル別ではその棚、購入月別では「この日／この月」（年表示では「この年」）を選び、共有先（Instagram フィード・ストーリーズ・X・写真に保存）を選んで、生成した画像を確認してから投稿する。共有画像に「買いたい」の本は含めない

### 6.9 買いたい本

- まだ買っていない本（所持状況が「買いたい」）を集めて見せる**システム棚**。最初からあり、削除・名前変更はできない（英語名: Wishlist）
- 本の**入れ物ではない**。「買いたい」の本もそれぞれジャンルを持っていて、買いたい本はそれを集めて表示しているだけ
- 閲覧画面の縦スワイプには、本が1冊以上あるときだけ出る。位置は未分類の前
- 詳細ページの「**購入した**」ボタンを押すと、所持状況が購入済みになり、購入日がその日になり、その本のジャンルの棚に並ぶ。画面下に「購入済みにしました／取り消す」の通知を出す
- 編集画面で所持状況を「購入済み」に切り替えたときも同じ動きになる
- 以前あった「購入後の棚」という考え方は廃止（ジャンルに統合した）

## 7. デザイン上の難所（必ず考慮してほしい状態）

| 状態 | 内容 |
| :-- | :-- |
| 表紙の縦横比がばらばら | 文庫・新書・単行本・大判・漫画・洋書が1つの棚に混ざる。自分で撮った写真なので、明るさや色味にもばらつきがある |
| 冊数が少ない／多い | 数冊の棚、100冊以上の棚。初回起動時（本が1冊もない状態）の見せ方 |
| 本が出たり消えたりする棚 | 0冊のジャンルは閲覧画面に出ない。最初の1冊を入れると現れ、最後の1冊が出ていくと消える |
| ジャンルが多い | 初期で28件＋ユーザーのジャンル。「棚を選ぶ」リストで迷わずに選べること（移動先を選ぶときは0冊のジャンルも並ぶ） |
| 買いたい本 | いろいろなジャンルの「買いたい」本が1つの棚に集まる。「購入した」を押すと本がこの棚から消えてジャンルの棚へ移る流れと、取り消しの通知 |
| 編集画面の「買いたい」の状態 | 購入日の行が入力できない状態の見せ方 |
| 購入月別 | 本がない月・年は飛ばす。年にまとめたとき、1年分の本が横一列に長く並ぶ。月・年の名前は押せない（「▾」なし） |
| 長い題名・英語表示 | 長い題名、英語の長いボタン名やラベルでも切れないこと |
| 文字認識の候補 | 候補が届く前、届いた後、候補なし、の3状態 |
| 四隅の検出失敗 | 手動で四隅を調整する画面 |
| 共有画像の冊数 | 1冊でも数十冊でも映える構成。4:5 と 9:16 の両方で成り立つこと |
| アクセシビリティ | 文字サイズの拡大（Dynamic Type）に対応すること。VoiceOver（読み上げ）では本を題名で読み上げる |

## 8. デザインしないもの（このアプリにない機能）

- SNS機能（フォロー・タイムライン・いいね・コメント・レビュー共有）
- ランキング・バッジ・ストリーク（連続記録）などのゲーム要素
- 星評価・感想・メモ
- 読んだ／読みたい等の読書ステータス、読書タイマー、ページ進捗（「買いたい」は所持状況で、読書ステータスとは別）
- 統計・グラフ・年間の振り返り（将来の候補だが今回は作らない。購入月別は本を月ごとに並べて見るだけで、集計は出さない）
- バーコード・ISBN読み取り、著者・出版社の表示や自動取得
- データ追加日の表示、「よみ」の表示・編集
- 題名のない本の表示（題名は必須）
- ログイン・アカウント・同期設定
- 広告、おすすめ
- CSV などのエクスポート・インポート
- ウィジェット、iPad 専用レイアウト

## 9. 販売・ブランドの前提

- App Store の**有料アプリ（買い切り600円）**。無料版・アプリ内課金・サブスクはない（購入を促す画面や課金画面は不要）
- 「通信ゼロ・登録不要・データは端末の中だけ」は、ストアや宣伝での訴求点になる
- 共有画像がSNSで広まることが主な宣伝手段。**共有画像そのものが広告**になる前提でデザインする
- アプリ名は未定。決まり次第、共有画像とアイコンに反映する
- App Store の説明文・スクリーンショットも日本語・英語の両方で用意する

## 10. デザインで決めてほしいこと

1. 本棚の見せ方（棚板の表現、表紙の並べ方、縦横比がばらばらな表紙の揃え方、「ずらっと並ぶ」感じの出し方）
2. 撮影から棚に並ぶまでの演出
3. 並べ替え時の手触り（持ち上げ・移動・置くときの動き）
4. 画面上の呼び方を「棚」と「ジャンル」のどちらにするか
5. 買いたい本棚の見せ方（ジャンルの出し方、「購入した」までの流れ）
6. 検索の所持状況の絞り込みの置き場所
7. 共有の入口と流れ（範囲の選択 → 共有先の選択 → 画像の確認）
8. 共有画像（と動画）のレイアウト（別タスク）
9. 色・書体・余白などのトーン（日本語の書体を活かすかどうかを含む）
10. アプリアイコン（アプリ名が決まった後）

## 11. 書籍のデータ構造（2026-11-10 更新・承認待ち）

> 詳細は `.dev/requirements.md` §10 を参照。

| 項目 | 必須 | 画面に出すか | 入り方 | 後から編集 |
| :-- | :-- | :-- | :-- | :-- |
| 表紙画像 | ◯ | 出す | 撮影 or ライブラリ | 撮り直し可 |
| 題名 | ◯ | 出す | 文字認識の候補を初期値に、ユーザーが確定（1〜200文字） | 可 |
| よみ | ◯ | **出さない** | 題名から端末内で自動で作る。題名を直すと作り直す | 不可（ユーザーは見えない） |
| ジャンル（＝棚） | ◯ | 出す | 登録先のジャンル（なければ未分類） | 可 |
| 所持状況 | ◯ | 出す | 登録待ちの一覧の「購入済み」チェック（初期値は購入済み） | 可 |
| 購入日 | 購入済みの本のみ | 出す（購入済みのみ） | 登録した日。「買いたい」から購入済みにしたときはその日 | 可（購入済みのとき） |
| データ追加日 | ◯ | **出さない** | 登録した日時を自動で記録 | 不可 |
| ジャンル内の並び順 | ◯ | （並びとして出る） | ジャンルの末尾に入る | 並べ替えで変わる |

- **ジャンル:** これまでの「棚」と同じもの。1冊は1つのジャンルにだけ入る
- **所持状況:** 購入済み／買いたい、の2値。ジャンルとは別の軸として、アプリに組み込みで持つ。欲しい本も登録できる
- **買いたい本:** 所持状況が「買いたい」の本を集めて見せるシステム棚（§6.9）。ジャンルの棚には購入済みの本だけが並ぶ
- **よみ:** 題名順の並べ替えと検索のための読みがな。自動で作るので、人名や難しい読みでは間違うことがある（画面に出さないので、ユーザーは直せない）
- **データ追加日:** 「データ追加日順」の並べ替えにだけ使う。画面には出さない
- 旧「棚に加えた日」は、購入日とデータ追加日の2つに分けた。画面に出る日付は購入日だけ
- 文字認識の題名候補は、登録を確定するまでの一時的な値で、本のデータとしては残さない
