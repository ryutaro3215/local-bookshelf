# 共有画像（シェア画像）デザイン調査

調査日: 2026-11-10
対象: local-bookshelf（仮称）の「ジャンル別・月別・日別」共有画像

> 記号の意味
> - **【確認済】**: 公式ドキュメントなど一次情報で確かめた
> - **【二次情報】**: 解説記事・ブログなど公式以外の情報。複数の記事で一致したもの
> - **【未確認】**: 情報が食い違う、または見つからなかった。実機での確認が必要

## 1. 結論

1. **基本は静止画、ストーリーズ向けだけ「数秒の短い動画」を任意で出す**のがよいと考えます。静止画は1枚で「棚」の全体が伝わり、Instagram フィード・X・写真保存のどこでもそのまま使えます。動画（表紙が1冊ずつ棚に並んでいく5〜8秒程度の動き）は、setlog のように「自動でできあがる気持ちよさ」を出せる追加の見せ場として、第2段階で入れるのが現実的です。
2. **出力サイズはまず2種類**です。縦長の **4:5（1080×1350）** をフィード・X・保存の共通サイズにし、**9:16（1080×1920）** をストーリーズ専用にします。どちらも、上下の端に大事な情報を置かないようにします。
3. **表紙の縦横比はそろえず、高さをそろえて横に並べる**（書店の平台・面陳列のような見せ方）のが、このアプリらしさと「映え」を両立できます。冊数が増えたら段数を増やして縮小し、50冊を超えたら「全部見せる」モザイク表示に切り替えます。
4. **ストーリーズへの直接送信には Meta の App ID（無料）が必要です**（2023年1月から必須）【確認済】。App ID はアプリ内に文字列として書き込むだけで、通信は発生しません。ただし Meta の開発者登録（Facebook アカウントが必要）が要ります。フィードと X には、iOS 標準の共有シート経由で画像を渡せます。
5. ロゴは**右下に小さく1か所だけ**入れ、文字は「2026年11月に買った本 / 12冊」のように**事実だけ**を書きます。評価やランキングのような要素は入れません。

### 2-2. できあがる動画の見た目

- **縦長の動画**として書き出され、Instagram や TikTok にそのまま投稿しやすい【二次情報】。
- **時刻が大きく表示される**。グループでは画面中央に太字、1人用では右端に出る【二次情報】。「この2秒は何時のものか」が一目でわかるのが特徴。
- グループの場合は、**同じ時刻のメンバーの映像が分割画面で並ぶ**【二次情報】。友だち同士で服の色をそろえる「レインボーチャレンジ」のような遊びも生まれている。
- 各クリップには短いキャプション（一言）をつけられる。
- BGM は付かず、音楽は別のアプリで足す必要がある、という指摘あり【二次情報】。
- **ロゴや透かし（ウォーターマーク）の有無・位置は、調べた範囲では確認できませんでした【未確認】**。実際に書き出した動画で確認が必要です。

### 2-3. なぜ広がったのか

1. **手間がほぼゼロ**: 撮るのは1日数分。編集は全部アプリが自動でやる。「自分で作った感」がないのに、できあがりは作品っぽい。
2. **形式（フォーマット）そのものが目印になる**: 「2秒ずつ・時刻つき・縦長」というお決まりの形が一目で setlog だとわかるので、ロゴが目立たなくても宣伝になる。
3. **盛らない・加工しない安心感**: 撮り直しできないので、気負わずに見せられる。BeReal の流れをくむ「ありのまま」志向。
4. **閉じた場所で作り、開いた場所（X・Instagram・TikTok）で見せる**: アプリ内は友だちだけ。できあがった動画を外の SNS に出すことで広がる。
5. **企業・キャラクターも真似した**: 大韓航空やアドベンチャーワールドなどが「setlog 風」の動画を投稿し、形式の認知が広がった【二次情報】。

### 2-4. このアプリが学べること

- **「単位」を決めてアプリが自動でまとめる**（setlog = 1日、本アプリ = 1日・1か月・1ジャンル）。ユーザーは「共有」を押すだけ、が理想。
- **時刻や日付を大きく出すと「記録」らしさが出る**。本アプリでは「2026.11.08」「2026年11月」などを主役級の文字にする価値がある。
- **形式が一目でわかれば、ロゴは小さくてよい**。「表紙が面陳列で並んだ、木目や棚板のある画像」が本アプリのお決まりの形になれば、それ自体が広告になる。
- **加工しない良さ**: ユーザーの撮った表紙写真がそろっていなくても、それが「自分の本棚らしさ」になる見せ方を考える（4章）。

### 3-2. 要点

- **「見立て」が強い**: フェスのポスター（Instafest）、レシート（Receiptify）、本屋の平台（本アプリ）のように、ひと目で「○○っぽい」とわかる形は強い。本アプリの見立ては**「書店の面陳列」「自分の本棚」**。
- **縦長で、1枚で完結する**: Wrapped のように何枚も見せる形式は年1回のイベント向き。日常的な共有では「1枚で全部わかる」方がよい。
- **冊数の多さはそれだけで価値**: Goodreads のモザイクのように、「こんなに買った」が伝わること自体が自慢になる。逆に StoryGraph のように表紙枠を少なく制限したり、多いと読めなくなったりするのは不満につながる。
- **主役はユーザーのもの、アプリは脇役**: Strava（ユーザーの写真が主役）、Letterboxd（ポスターが主役）のように、ブランドは小さく。本アプリでは**ユーザーが撮った表紙写真が主役**。
- **自動で文章を作らない**: Fable の炎上が示すように、自動で「感想」や「いじり」を付けるのは危うい。本アプリは日付・冊数・ジャンル名など**事実だけ**を載せるのが安全で、「SNS 的なものが苦手」という利用者像にも合う。
- **日本の読書サービスは「画像で見せる」が弱い**: 読書メーターはテキストとリンクのみ。表紙が並んだ1枚絵を手軽に作れること自体が、ここでの差別化になる。

## 4. 本の表紙を映えさせるレイアウトの考え方

### 4-1. 大前提: 縦横比のばらつきをどう扱うか

本の縦横比はおおよそ次のとおり（いずれも 横:縦）。

| 種類 | 寸法の目安 | 縦横比 |
|---|---|---|
| 文庫 | 105×148mm | 約 1:1.41 |
| 新書 | 103×182mm | 約 1:1.77（細長い） |
| 四六判（単行本） | 127×188mm | 約 1:1.48 |
| 漫画（B6・新書判） | 112〜128×174〜182mm | 約 1:1.4〜1.6 |
| 洋書ペーパーバック | 約 108×175mm | 約 1:1.6 |
| 大判・画集・絵本 | さまざま | 横長や正方形もある |

考え方は3つあります。

| 方法 | 見え方 | 向き・不向き |
|---|---|---|
| **A. 高さをそろえ、幅はそのまま（推奨）** | 書店の平台・本棚のように、背の高さがそろい横幅がばらつく。リアルな「棚」に見える | 本アプリの「面陳列」の世界観にいちばん合う。左右の端が少しずつずれるが、それが本物らしさになる |
| B. 同じ大きさの枠に入れ、余白で調整 | 枠の中で表紙が小さくなったり余白ができたりする | 整って見えるが、新書などの細長い本が小さく見える |
| C. 同じ枠に切り抜く（トリミング） | ぴったりそろう | **表紙の一部（タイトル・帯）が切れるので不可**。表紙を覚えている利用者には致命的 |

→ **基本は A**。行ごとに「高さをそろえて横に詰め、行の幅が足りなければ少し縮める」方法（写真ギャラリーでよく使われる「行ごとのそろえ方」）で並べます。

### 4-2. 写真のばらつき（明るさ・色・傾き）への対策

ユーザーの撮った写真は、明るさや色味、影の入り方がそろいません。加工しすぎると「その人の本」らしさが消えるので、**軽く整えて、置き方で一体感を出す**方針がよいです。

- **影と台座で「物」として見せる**: 表紙の下に薄い影を落とし、棚板（細い横線や木目）の上に「置いた」ように見せる。写真ごとの差より「棚に並んだ本」の印象が勝つ。
- **背景で全体をまとめる**: 背景は無地の落ち着いた色（生成り・濃紺・墨色など数種類）か、表紙の色から自動で選んだ色にする。表紙の色がばらばらでも、背景が1色だとまとまって見える。
- **軽い自動補正は撮影時（取り込み時）に1回だけ**: 傾き補正・四隅の切り抜き（書類スキャンのような処理）、極端な暗さの補正程度。共有画像を作るたびに加工はしない。
- **角を少し丸め、細いふちをつける**: 写真の端の汚れや背景の写り込みを目立たなくする。
- **表紙が未撮影の本**: タイトル文字だけの「仮の表紙」を、背景に合わせた落ち着いた色で作る（色の濃さを固定すると、並んだときに浮かない）。

### 4-3. 冊数別のレイアウト

縦長 4:5（1080×1350）を基準にした目安です。9:16 でも考え方は同じで、縦に1〜2段増やします。

| 冊数 | おすすめの型 | ポイント |
|---|---|---|
| **1冊** | **主役1冊を大きく中央に**（画像の高さの55〜65%）。台座・影をつけ、下に日付とタイトル | 1冊は「今日の1冊」として最も映える。タイトルを大きめに載せてよい（データ上タイトルは必須なので必ずある） |
| **2〜4冊** | **1段に横並び**、または少し重ねて扇形に。平台に置いたような見せ方 | 冊数が少ないうちは表紙を大きく。重ねる場合も表紙の顔（タイトル部分）は隠さない |
| **5〜12冊** | **2〜3段の棚**。各段の高さをそろえて詰める | 本アプリの「棚」画面そのものに近い見た目にすると、アプリの宣伝として一番わかりやすい |
| **13〜30冊** | **4〜6段の棚**。表紙はかなり小さくなるが、色と形で「たくさん」が伝わる | 個々のタイトルは読めなくてよい。冊数を大きな数字で出す |
| **31〜50冊** | 段数を増やした棚、または表紙の間をつめた**密な面陳列** | 棚板の線は細く・薄く。余白を減らして「壁一面」の印象に |
| **51冊以上** | **モザイク（敷き詰め）**。全冊を小さく敷き詰め、中央か下に大きな数字（例: 「128冊」） | Goodreads 型。全部を見せることが価値。数が多すぎて1冊が極端に小さくなる場合（例: 200冊超）は「最新の○冊＋残り○冊」の表記も検討 |

補足:

- **「全部載せる」を原則にする**: StoryGraph の不満（表紙枠が少ない・表紙が読めない）を避ける。選ぶ手間をかけさせない。
- **並び順**: 日別・月別は「買った順」、ジャンル別は「棚での並び順（ユーザーの並べた順）」をそのまま使う。アプリの棚と共有画像が一致していると、アプリを知らない人にも「こういうアプリなんだ」と伝わる。
- **自動で最適な型を選び、ユーザーは2〜3案から選べる**くらいがよい（setlog のように基本は自動）。

### 4-4. 文字（日付・ジャンル・冊数）の載せ方

- 載せるのは **見出し1行＋補足1行＋ロゴ** まで。
  - 日別: 「2026.11.08」＋「3冊」
  - 月別: 「2026年11月」/「November 2026」＋「12冊」
  - ジャンル別: ジャンル名（例: 「ミステリ」）＋「48冊」
- **数字を大きく、言葉は小さく**。setlog の時刻表示のように、日付・冊数を「記録」としてはっきり見せる。
- 書体は、日本語は明朝系（本らしさ）またはすっきりしたゴシック、数字は等幅か細身の書体に。iOS 標準のヒラギノ明朝・ヒラギノ角ゴ・SF Pro などで、追加の書体ファイルなしでも作れる。
- 「購入済み」「ほしい本（ウィッシュリスト）」が混ざる共有単位（ジャンル別など）では、**初期設定では購入済みだけ**を載せるか、ほしい本は少し薄く表示するなど区別をつける（オーナー判断が必要）。
- 英語表示の場合は月名・数字の書式を切り替える（「12 books」など）。

### 4-5. ロゴの置き方

- 右下（または左下）に、画像の横幅の15〜20%以下の小さなワードマーク（文字のロゴ）。
- ストーリーズでは下端に返信欄などが重なるので、**下から約20%より上**に置く（5章）。
- 色は背景になじむ半透明。表紙より目立たせない。

| **X（画像1枚の投稿）** | **1080×1350（4:5）を推奨** | 4:5 | 1枚だけの画像は、縦横比 2:1〜3:4 の範囲ならタイムラインで切れずに表示される、という記事が多い。4:5 はこの範囲内。ただし公式ヘルプは今回取得できず、「4:5 まで」「中央を切る」など食い違う記事もある | 【未確認】（実機での確認が必要） |
| **写真に保存** | 1080×1350 を基本、ストーリーズ用 1080×1920 も選択可 | — | 保存後に他アプリで使われることを考え、フィード用と同じ 4:5 を既定に | — |

### 5-2. 実務上のおすすめ

- **4:5（1080×1350）を「共通サイズ」**にする。Instagram フィード・X・写真保存のすべてで使える。
- 4:5 の画像でも、**大事な要素（表紙の並び・日付・冊数）は中央の 3:4 の範囲（1012×1350 相当）に収める**と、Instagram の一覧表示でも切れない。
- **9:16（1080×1920）はストーリーズ専用**。上下の端（上約14%・下約20%）は背景色や棚の延長だけにする。
- 画質は余裕をもって作る（2倍の 2160×2700 で描いてから縮小する、または 1080 幅でも表紙写真は高解像度のまま使う）。Instagram や X は投稿時に再圧縮するので、細かい文字は小さくしすぎない（最小でも 24px 程度）。

### 5-3. 動画（短い MP4）を出す価値はあるか

| 観点 | 内容 |
|---|---|
| 良い点 | ストーリーズ・リールでは動きのあるものが目を引く。2025年のある調査では、ストーリーズの画像は動画より「次へ飛ばされる率」が高かった（画像 56.8〜66.7%、動画 50.5〜62.0%）【二次情報】。setlog のように「自動でできあがる動画」は、それ自体が楽しい体験になる |
| 悪い点 | 開発の手間が大きい（動画の書き出し処理、端末の発熱・時間、保存容量）。X や Instagram フィードでは静止画の方が「1枚で全部わかる」。冊数が多いと動画が長くなる |
| 結論 | **最初は静止画のみで十分。第2段階で「ストーリーズ用の5〜8秒動画」を追加**するのが費用対効果がよい。動画は「表紙が1冊ずつ棚に置かれていき、最後に完成した棚（＝静止画と同じ絵）で止まる」形にすると、最後の1コマがそのまま静止画として成立する |

動画の具体案（第2段階）:

- 長さ: 5〜8秒（Meta の直接送信の上限はストーリーズ20秒、リールは3〜60秒）。
- 動き: 表紙が下から「ストン」と置かれる → 最後に日付と冊数がふわっと出る → 1〜2秒静止。
- 50冊以上: 1冊ずつではなく、段ごと・まとめて表示して長さを一定に保つ。
- 音: なし（setlog も BGM なし。ユーザーが Instagram 側で音楽を付けられる）。
- iOS 上の端末内処理（AVFoundation という標準の動画処理機能）だけで作れるため、通信は不要。

## 6. 技術的な実現性（通信なし・アカウントなしで実現できるか）

### 6-1. Instagram ストーリーズへの直接送信（Meta「Sharing to Stories」）

**結論: 実現できる。ただし Meta の App ID が必須で、Meta の開発者登録が必要。**

| 項目 | 内容 | 確度・出典 |
|---|---|---|
| App ID の要否 | **必須**。公式ドキュメントに「2023年1月から、Instagram ストーリーズに共有するには Facebook App ID の指定が必要」とある。指定しないと「このアプリは現在ストーリーズへの共有に対応していません」というエラーが利用者に表示される | 【確認済】Meta 公式（Sharing to Stories） |
| 仕組み | ① 画像（や動画）を iOS のクリップボード（ペーストボード）に入れる → ② `instagram-stories://share?source_application=<App ID>` という URL で Instagram を開く → ③ Instagram のストーリーズ作成画面に画像が入った状態で開く | 【確認済】Meta 公式 |
| クリップボードに入れるもの | `com.instagram.sharedSticker.backgroundImage`（背景画像）、`com.instagram.sharedSticker.stickerImage`（重ねる画像）、`com.instagram.sharedSticker.backgroundTopColor` / `backgroundBottomColor`（背景の上下の色。同じ色なら単色、違えばグラデーション） | 【確認済】Meta 公式 |
| 背景動画 | ストーリーズ向けページでは「背景動画に対応」と書かれているが、例のコードには動画用のキー名がない。リール向けの公式ドキュメントでは `com.instagram.sharedSticker.backgroundVideo` が使われており、ストーリーズでも同じキーと考えられる | キー名は【未確認】（実機確認が必要） |
| Info.plist（アプリの設定ファイル） | `LSApplicationQueriesSchemes` に `instagram-stories` を追加（Instagram が入っているかを確かめるため） | 【確認済】Meta 公式 |
| 有効期限 | 公式の例では、クリップボードの中身を5分で消える設定にしている | 【確認済】Meta 公式 |
| 通信の有無 | App ID は文字列としてアプリに書き込むだけ。本アプリ自体は通信しない（Instagram アプリ側の通信は別） | 仕組みからの判断 |

**App ID の登録で必要なこと**（公式ページで手順の細部は確認しきれず、一部【未確認】）:

1. Meta for Developers（developers.facebook.com）に登録する。**Facebook アカウントが必要**。
2. 「アプリを作成」して App ID（数字の列）を取得する。費用は無料。
3. Meta の SDK（部品集）の組み込みは、Sharing to Stories だけなら**不要**（URL を開くだけの仕組みのため）。SDK を入れないので、アプリが勝手に通信することもない。
4. リールへの直接送信の公式ドキュメントには「**Meta アプリが公開（Live）状態でないと利用者は共有できない**」と明記されている。公開状態にするにはプライバシーポリシーの URL などの登録が求められるのが一般的。ストーリーズでも同じ条件かは【未確認】。
5. Meta によるアプリ審査（App Review）は、公式ページでは言及なし【未確認】。

注意点:

- App ID を発行した Meta 側のアプリ設定が無効化・削除されると、共有が使えなくなる可能性がある（アプリ側の更新なしに機能が止まる外部依存）。
- iOS では、他のアプリがクリップボードを読むときに「ペーストを許可しますか」という確認が出ることがある。Instagram 側の挙動として出るかどうかは【未確認】。
- App Store の説明や「通信しません」という約束の書き方: 「本アプリ自体は通信しないが、共有先の Instagram アプリは通信する」ことを明記しておくと誤解がない。

### 6-2. Instagram フィードと X への共有（iOS の共有シート）

**結論: iOS 標準の共有シート（UIActivityViewController）に画像を渡せば、Instagram・X とも画像が入った状態で投稿画面を開ける。登録や App ID は不要。**

| 共有先 | 方法 | 画像の事前入力 | 文章の事前入力 | 確度 |
|---|---|---|---|---|
| **Instagram フィード** | 共有シート → Instagram（Instagram の共有機能拡張） | できる | **できない**（Instagram は外部アプリからの説明文を受け付けない。複数の開発者報告・ライブラリの説明で一致） | 【二次情報】 |
| Instagram フィード（別ルート） | 公式ドキュメントでは「画像を `.ig`（Instagram 専用なら `.igo`）という拡張子のファイルにして、文書を開く仕組み（UIDocumentInteractionController）で渡す」方法が案内されている | できる | できない | 【確認済】Meta 公式（ただし古い方式で、今の Instagram で動くかは【未確認】） |
| Instagram フィード（非公式） | 写真に保存してから `instagram://library?LocalIdentifier=...` で開く | できる | できない | **非公式で、動かなくなった報告もある**。使わない方がよい |
| **X** | 共有シート → X | できる | できる（共有シートに文章も一緒に渡すと、X の投稿欄に入る。一般的な挙動） | 【未確認】（実機確認が必要） |
| X（別ルート） | 公式の「Web Intent」（`https://x.com/intent/tweet?text=...`） | **できない**（文章と URL のみ） | できる | 【確認済】X 公式 |
| **写真に保存** | 共有シートの「画像を保存」、またはアプリ内ボタンから直接保存 | — | — | 写真への追加には Info.plist に `NSPhotoLibraryAddUsageDescription`（保存の許可を求める理由）が必要 |

注意点:

- **Instagram 向けの説明文やハッシュタグ**は事前入力できないので、「#わたしの本棚 などをコピーしました。貼り付けて使えます」と、文章をクリップボードにコピーして案内する方法がよく使われる。ただしこれはストーリーズ送信のクリップボード利用と重なるので、順番に注意。
- 共有シートに**画像と文章を両方渡すと、Instagram 側で不具合が出る**という報告がある【二次情報】。Instagram 用には画像だけを渡す、など送り先ごとに中身を変える工夫が必要（共有シートでは送り先ごとに渡す中身を変えられる仕組みがある）。
- 現在の Instagram の共有機能拡張は、共有シートから開くと「フィード／ストーリーズ／メッセージ」を選べる形になっている、という情報がある【未確認】。これが使えれば App ID なしでもストーリーズに出せる可能性があるが、9:16 の画像がきれいに全画面で入るかは要確認。
- 静止画・動画の作成はすべて端末内（SwiftUI の ImageRenderer や Core Graphics、AVFoundation）でできるため、通信は不要。

## 7. このアプリへの提案

### 7-1. 共通の方針

- **出力**: 4:5（1080×1350）を既定。ストーリーズを選んだときだけ 9:16（1080×1920）。
- **共有の流れ**: 共有画面で「型（2〜3案）」「背景色（3〜5色）」を選ぶ → 下に「ストーリーズ」「Instagram」「X」「保存」「その他」のボタン。ストーリーズは Meta の直接送信、それ以外は共有シート。
- **文字**: 見出し（日付・月・ジャンル名）＋冊数＋小さなロゴのみ。評価・感想・ランキングは入れない。
- **お決まりの形**: どの単位でも「棚板＋面陳列の表紙＋大きな日付/数字」という共通の見た目にし、見ただけで本アプリだとわかるようにする（setlog の「形式が目印」に倣う）。

### 7-2. 日別（その日に買った本）

日別は冊数が少ない（1〜5冊程度）ことが多いので、**1冊1冊を大きく見せる**。

| 案 | 内容 | 向く冊数 |
|---|---|---|
| **D1: 平台（推奨）** | 書店の平台のように、表紙を大きく1段に並べる。1冊なら中央に大きく。下に「2026.11.08」を大きく、その下に「3冊」 | 1〜5冊 |
| D2: 買い物袋・レシート風 | 縦長の紙（レシートのような帯）の上に表紙を縦に並べ、日付と冊数を印字風に。Receiptify の「見立て」に近い | 1〜4冊 |
| D3: 少し重ねた扇形 | 表紙を少しずつ傾けて重ねる。手に持った本の束のような印象。表紙のタイトル部分は隠さない | 2〜5冊 |

日別の場合、6冊以上なら自動的に月別と同じ「棚」型に切り替える。

### 7-3. 月別（その月に買った本）

月別は数冊〜数十冊まで幅があるので、**冊数に応じて自動で段数を変える棚**を基本にする。

| 案 | 内容 | 向く冊数 |
|---|---|---|
| **M1: 月の棚（推奨）** | 上部に「2026年11月」と大きな冊数「12」、その下に2〜6段の棚。買った順に左上から並ぶ | 3〜40冊 |
| M2: カレンダー型 | その月のカレンダーの日付マスに、その日に買った本の表紙を小さく入れる。買わなかった日は空き。「いつ・どれだけ買ったか」が見える | 5〜30冊程度（同じ日に多数あると窮屈） |
| M3: モザイク＋大きな数字 | 全冊を敷き詰め、中央に半透明の帯で「11月 / 58冊」。多読（多買い）の自慢に向く | 40冊以上 |

### 7-4. ジャンル別（1つの棚の本）

ジャンル別は冊数が多くなりやすく、「自分の棚そのもの」を見せたい単位。

| 案 | 内容 | 向く冊数 |
|---|---|---|
| **G1: 棚の写し（推奨）** | アプリの棚画面とほぼ同じ見た目で、ユーザーが並べた順に全冊を表示。上にジャンル名、右上に冊数。アプリの宣伝として最もわかりやすい | 5〜50冊 |
| G2: 壁一面モザイク | 棚板を消して表紙を壁一面に敷き詰める。50冊以上でも全部見せる。下に「ミステリ 128冊」 | 50冊以上 |
| G3: 選んだ数冊を主役に | 棚から「表紙の顔」として数冊（ユーザーが選ぶか、最新の数冊）を大きく前面に置き、残りを背景に小さく並べる。Letterboxd の「4本」に近い見せ方 | 冊数を問わない |

### 7-5. 静止画と動画、どちらを推すか

**静止画を推します。** 理由:

1. 共有先4つのうち3つ（Instagram フィード・X・写真保存）は静止画の方が向いている。
2. 「1枚で本棚が全部わかる」ことが、本アプリの価値（表紙で本を覚えている人の自慢）にいちばん合う。
3. 個人開発で品質（上位3つの優先事項の1つ）を出すなら、まず静止画の仕上がりに集中した方がよい。

そのうえで、**第2段階でストーリーズ用の短い動画（5〜8秒、最後のコマが静止画と同じ）を追加**すると、setlog のような「自動でできあがる気持ちよさ」と、ストーリーズで目に留まる効果を足せます。
