# 知っておいてほしいこと（申し送り一覧）

開発中に見つかった「今すぐのエラーではないが、知っておくべきこと・あとで対応が要ること」をタスク形式で集める場所。
新しく見つかったものは、下の「追記ルール」に従ってこのファイルに追記する。

---

## 追記ルール（必ず守る）

1. **1件 = 1ブロック**。下の「書式」をそのまま使い、項目を省略しない（該当なしは「なし」と書く）
2. **番号**: `N-` + 3桁の通し番号（N-001, N-002 …）。番号は使い回さない。完了・取り下げになっても番号は変えない
3. **置き場所**: 状態に合わせて下のセクションに入れる
   - 「未対応」— まだやることが残っているもの。さらに **区分** ごとの小見出しの下に置く
   - 「完了・取り下げ」— 対応が終わったもの、対応しないと決めたもの。未対応から **移動** する（消さない）
4. **区分**（小見出し）は次の5つだけを使う。増やすときはこのルールに先に追記する
   - `判断待ち` — オーナー（ユーザー）が決める必要があるもの
   - `計画・ドキュメント` — plan.md / requirements.md / design-brief.md などの更新が要るもの
   - `実装` — コードの変更が要るもの
   - `確認・検証` — 実機確認・計測など、試して確かめる必要があるもの
   - `運用・環境` — 開発の進め方・ツールの使い方に関する注意
5. **チェックボックス**: 未対応は `- [ ]`、完了は `- [x]`、取り下げは `- [x] ~~見出し~~` とし、「結果」に理由を書く
6. **日付** は `YYYY-MM-DD` の絶対日付で書く（「昨日」「来週」は使わない）
7. **期限** はタスク番号（例: `T5 着手前`）か、`リリース前` / `随時` のどれかで書く
8. 1つの項目が複数のことを含むときは分ける。1ブロックに1つの対応だけ
9. 追記したら、末尾の「更新履歴」に1行足す

### 書式

```markdown
- [ ] **N-000 見出し（1行で何の話か）**
  - 発生: YYYY-MM-DD ／ 出どころ: <T番号のレビュー・ビルド記録・オーナーの指示 など>
  - 内容: <何が起きているか>
  - 影響: <放っておくと何が困るか。困らないなら「動作への影響なし」>
  - 対応: <何をするか>
  - 担当 / 期限: <オーナー・dev-architect・dev-builder など> ／ <T番号 or リリース前 or 随時>
  - 結果: <完了・取り下げのときに書く。未対応なら「-」>
```
