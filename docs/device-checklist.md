# 実機での確認の手順（チェックリスト）

作成: 2026-11-19。対象は docs/notices.md の「確認・検証」のうち、実機が要るもの。
上から順に進めると、1回の作業でまとめて確かめられる（目安: 半日）。結果は各項目の「記録先」に書き、終わった申し送りは notices.md の「完了」に移す。

- 使う端末: **iPhone 13 相当**（requirements N1 の基準機）。iOS 26 以上
- 用意するもの: Mac（Xcode 27）、USB ケーブル、紙の本 10冊ほど（題名が横書き・縦書き・装飾書体のものを混ぜる）、Instagram と X のアプリ（ログイン済み）
- 進め方の注意: エージェントが作業している間は Xcode を閉じておく（N-012）

## 0. 準備（N-011・N-094）

- [ ] iPhone の 設定 → プライバシーとセキュリティ → **デベロッパモード** をオンにして再起動する
- [ ] iPhone を Mac につなぎ、「このコンピュータを信頼」を押す
- [ ] Xcode で Bookshelf.xcodeproj を開き、ターゲット Bookshelf → Signing & Capabilities でチーム（P45Y47YJDM）を選ぶ。BookshelfUITests も同じチームにする
  - 初回は、自動署名で App ID に **Data Protection** の機能が足される（Bookshelf.entitlements の設定）。エラーが出たら内容を控える
- [ ] 実行先に iPhone を選んで ▶︎（Run）。ホーム画面にアプリが入り、起動することを確かめる
- [ ] 端末の ID を控える（あとでテストのコマンドに使う）: ターミナルで `xcrun xctrace list devices`
- 記録先: .dev/build-log.md（「実機での確認」の項を新しく作る）

## 1. 初回の起動とカメラの許可（N-076・L 行／O 行）

アプリを一度消してから入れ直し、日本語の端末で始める。

- [ ] ようこそ（L-1）→「最初の1冊を登録する」→ 棚を選ぶ（L-2）→「この棚で撮影する」
- [ ] カメラの許可の説明（O-1）→「カメラを許可する」→ **OS のダイアログ（O-2）** が出る
  - [ ] 「許可」を選ぶ → 撮影画面（L-3）になる → 1冊撮ると登録待ちへ進む → 登録 → 「最初の1冊が棚に並びました」（L-4）
- [ ] アプリを消して入れ直し、O-2 で **「許可しない」** を選ぶ → 撮影画面が「カメラへのアクセスがオフになっています」（O-3）になる
  - [ ] 「設定を開く」で設定アプリのこのアプリの画面が開く。カメラをオンにして戻ると撮影できる
  - [ ] 「写真ライブラリから選ぶ」でも登録できる
- [ ] Figma の L 行・O 行と見比べる（画面写真は notices N-076 の場所）
- 記録先: build-log、notices N-076

## 2. 撮影と登録（N-037・N-092・N-042・N-070・N-038・N-041）

- [ ] **連続撮影の速さ**（N-092・N-037。基準: シャッターを押してから次に押せるまで1秒以内）
  - Mac の「コンソール」アプリで iPhone を選び、メニューの アクション → **「情報メッセージを含める」** をオンにし、検索欄に `撮影 → 次の撮影可能` と入れてから「開始」を押し、10冊続けて撮る
  - 出てくる「撮影 → 次の撮影可能: n ms」の値を10回分控える（最大と中央値）
  - 手で押してみて、待たされる感じが無いかも書く
- [ ] **表紙の自動検出**（N-042。目標: 正しく切り抜ける率 6割以上）
  - 10冊を、机の上・手に持って・背景が本と似た色、で撮る。枠（四隅の線）が表紙に合うか、登録待ちの表紙が正しく切れているかを数える
  - 外れた本は、登録待ちの行の **表紙を押して四隅を直せる** ことを確かめる（N-041。2026-11-19 追加）
  - 四隅を見つけられないとき N 画面になり、ルーペを見ながら角を合わせて「この範囲で使う」で直せる
- [ ] **題名の読み取り**（N-022）: 10冊のうち、題名の候補の1番目が正しかった数・候補の中にあった数を控える（横書き・縦書き・装飾書体を分けて）
- [ ] 題名の入力（C-3）で **日本語入力**（変換中の文字・確定）がおかしくならない。未入力が今の本だけのとき「次の本へ」を押すと、題名欄にとどまって振動する
- [ ] ライブラリから **30枚** 選んで登録待ちに入るまでの時間と、途中でアプリが落ちないこと（N-070）
- [ ] Figma の A-2・A-3・A-4・C 行・N-1・N-2 と見比べる（N-038・N-070）
- 記録先: .dev/perf-report.md（撮影の速さ）、.dev/ocr-accuracy.md（検出・読み取り。実機の列を足す）、notices N-037・N-042・N-022・N-092

## 3. 閲覧・並べ替え（N-049・N-059・N-078・N-048）

本を30冊ほど入れた状態で行う（2 で登録した本でよい）。

- [ ] 左右にめくる・速く払う・上下で棚を変える手触り（N-049）
- [ ] **真ん中の大きな表紙がぼやけない**（N-048。2026-11-19 に縮小版を800px にした。ただし、それより前に登録した本は400px のまま）
- [ ] **右の5つの点**: 押すとその棚へ、上下になぞると棚が続けて変わる（N-044。2026-11-19 追加）。本をめくる操作と取り合わない
- [ ] 長押しで本を選ぶ → 左右で並べ替え・上で別の棚へ・下で削除。長押しの時間・ドラッグの量が自然か（N-059）
- [ ] グリッド表示で長押し → メニュー・ドラッグでの並べ替え（N-059）
- [ ] 100冊以上の棚でスクラバーをなぞる（N-049。性能の計測用の500冊で確かめられる → 7）
- [ ] 購入月別: ピンチで月と年が切り替わり、横めくり・縦スワイプと誤動作しない（N-078）
- [ ] Figma の B〜D 行・H 行・I 行・J 行・P 行と見比べる
- 記録先: notices N-049・N-059・N-078

## 7. 性能の計測（N-090）

Mac のターミナルで、リポジトリの場所から実行する（`<端末ID>` は 0 で控えた ID）。iPhone はロックを外し、画面を消さない設定（自動ロック: なし）にしておく。

```
xcodebuild test -project Bookshelf.xcodeproj -scheme Bookshelf \
  -destination "platform=iOS,id=<端末ID>" \
  -only-testing:BookshelfUITests/PerformanceTests
```

- [ ] 5件が通るか（最初に500冊を作るので数分かかる）。「PERF」で始まる行を控える
  - コールドスタート（基準1秒以内）・共有画像（3秒以内）・データ容量（300MB 以下）
- [ ] Xcode の Report ナビゲータで testShelfScrollingHitches を開き、**ヒッチ率（hitch time ratio）** を控える（シミュレータでは出ない）
- 注意: 実機では、性能用の500冊の表紙に Mac の実写サンプルを使えず、合成の表紙になる。データ容量は実写より小さく出るので、参考値として書く
- 記録先: .dev/perf-report.md §2（実機の列）。基準を超えたら dev-builder に改善を頼む

## 9. データ保護（N-094）

- [ ] 本を1冊以上登録した状態で、Xcode → Window → Devices and Simulators → iPhone → Installed Apps の Bookshelf → ⚙ → **Download Container**
  - または、Xcode でアプリを動かしたまま一時停止し、デバッガで次を実行する:
    `po try FileManager.default.attributesOfItem(atPath: <表紙のファイルのパス>)[.protectionKey]`
  - `NSFileProtectionComplete`（complete）になっていれば OK
- [ ] 端末をロックしてから開き直しても、アプリが正しく動く（ロック中に裏で動く処理は無い）
- 記録先: .dev/security-report.md（再監査の追記として。dev-security に頼む）
