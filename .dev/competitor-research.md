# 競合調査：ミニマル書籍管理アプリ（国内外）

> 出典: ユーザー提供の調査メモ（2026-11-09 受領）。アプリの実在・仕様・価格は未検証のため、企画を固める前にストアで裏取りすること。

## 前提
国内外を問わず、SNS機能や過度なゲーミフィケーション（ランキング・バッジ等）を排除し、**「個人の端末内での記録・整理」に特化したミニマルな書籍管理アプリ**には明確な支持層が存在する。

## 海外

| アプリ | 対応 | 特徴 | 仕様・課金 |
| :-- | :-- | :-- | :-- |
| **PageFlow** | iOS | 「読書をプロダクト化させない」がコンセプト。脱ソーシャル・オフラインファースト。他人のフィード、ストリーク（連続記録のプレッシャー）、広告、バッジが一切ない | データは端末内に保存、同期はiCloudのみ（ユーザー登録不要）。無料枠は同時進行5冊まで。無制限利用はサブスクではなく買い切り（Lifetime） |
| **Oku** | Web / iOS | タイポグラフィと余白の美しさに特化した「静かな本棚」。入力の手間を感じさせない落ち着いたUI。SNS交流を嫌うミニマリスト層から高評価 | — |
| **Bookmory** | iOS / Android | 読書タイマーとカレンダー表示に絞ったパーソナルログ。交流機能なし。何日に何ページ読んだかをカレンダーで振り返る | — |
| **Book Tracker / Lume** | Android / OSS系 | 既存アプリの肥大化・広告・SNS化に嫌気がさした個人開発者が作ったローカル完結型 | ISBNバーコード読取＋ローカル保存（またはGoogle Drive等の個人領域）のみ。外部サーバーなし |

## 国内
大手の「ブクログ」「読書メーター」がコミュニティ・感想共有サービスとして巨大化しており、その対極として単機能・プライベート重視の個人開発アプリが支持されている。

| アプリ | 対応 | 特徴 | 仕様 |
| :-- | :-- | :-- | :-- |
| **読書管理 Yomoo** | iOS / Android | 「会員登録・ログインなし」「SNS機能なし」を打ち出した個人専用アプリ | バーコード読取で登録、「読んだ」「読みたい」の最小限のステータスで管理。他人のレビュー・星評価が目に入らない |
| **読書管理ビブリア** | iOS | バーコード登録と1冊ごとの簡単なメモ・感想に絞ったロングセラー | アカウント不要・端末内完結。本の検索やメモの全文検索がスムーズで、無駄な通信なし |

## 個人開発への示唆
- **ペインの本質**: 読書愛好家の一部は「読書ログを他人に公開・共有したいわけではない」「SNSのタイムラインやおすすめアルゴリズムに邪魔されたくない」という強いインサイトを持つ。
- **作りやすさ**: ISBNバーコードのカメラ読取（Vision / ML Kit等）とローカルDB（SwiftData / SQLite）でサーバーなし・100%端末完結が可能。外部依存はGoogle Books API等の書誌データ取得程度に抑えられる。
- **マネタイズ**: 「広告なし」＋「買い切り（または年額数百円〜千円程度の少額サブスク）」で、複数本棚・詳細統計・CSVエクスポートをアンロックするモデルと相性がよい。

## market-research.md との突き合わせ（所感）
- 「SNSなし・登録なし・端末完結」は既に複数の競合が掲げている → **それだけでは差別化にならない**。追加の軸が必要。
- 差別化軸の候補（未検討）:
  - Crouton型のオンデバイスOCR（ページ・ハイライト・メモの撮影→テキスト化して全文検索できる形で保存）
  - HabitKit型の視覚表現（読書量のグリッド・ウィジェット）※ストリークの圧はPageFlowが否定しているので見せ方に注意
  - Oku型のタイポグラフィ重視（日本語の書体設計を活かす）
- 書誌データ取得（Google Books API / openBD / 国立国会図書館API 等）は外部通信になる → 「ローカル完結」の定義（データ保存は端末のみ、参照のための通信は許容、など）を決める必要あり。
