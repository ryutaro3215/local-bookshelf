## 1. 目的
本を大量に持ち、本を表紙（ジャケット）で記憶している読書好きが、**スマホに自分の本棚を作る**ためのiOSアプリ。
表紙を撮るだけで登録でき、本屋のように表紙がずらっと並ぶ棚を自分の手で作り上げ、眺め、映える1枚画像としてSNSに共有できる。

**品質の重心**: 機能数ではなく、棚を作り上げる操作感・並びの美しさ・共有画像の見栄え（細部のデザインと作り込み）。工数はここに優先配分する。

## 2. 前提・制約
- プラットフォーム: iOS（iPhone）のみ。iPadは動作はするが最適化しない
- 言語: **日本語・英語の両対応**（2026-11-10 オーナー指示。詳細は N7）。端末の言語設定に従って切り替える
- 実装: ネイティブ（Swift）。スタックは plan.md に記録（2026-11-09 承認）
- 想定データ規模: 1ユーザーあたり蔵書 〜500冊、棚 〜30個
- 課金: App Storeの有料アプリ（買い切り600円）。アプリ内課金・無料版なし
- **通信ゼロ**: アプリ自身は外部通信を一切行わない（詳細は §6）

## 3. 用語
- **本**: 表紙写真と題名を必須とし、内部項目のよみ（題名順ソート用・非表示）、データ追加日・所持状況・購入日（購入済みの本のみ）・所属する棚（＝ジャンル）・棚内の並び順を持つ（詳細は §10）（2026-11-10 整合修正）
- **所持状況**: 購入済み／買いたい の2値。棚とは独立した組み込みの軸（§10.3）（2026-11-10 整合修正）
- **棚**: ユーザーが作る本のまとまり（例:「小説」「技術書」「積読」）。名前・並び順を持つ
- **未分類**: どの棚にも入っていない本の置き場（システム棚。削除不可）
- **買いたい本**: 所持状況が「買いたい」の本を集めて見せるシステム棚。本の入れ物ではなく、「買いたい」の本もそれぞれジャンルを持つ。最初から存在し削除不可（2026-11-10 オーナー判断。§10.3）（2026-11-10 整合修正）
- **面陳**: 表紙を正面に見せて並べる陳列。本アプリの基本の並べ方

## 4. 機能要件（MVPスコープ）

### F1. 表紙撮影による登録
- F1-1 アプリ内カメラで表紙を撮影して本を登録できる
- F1-2 撮影時に表紙の四隅を端末内で自動検出し、台形補正・トリミングした画像を表紙として保存する。自動検出に失敗した場合は手動で四隅を調整できる
- F1-3 **連続撮影モード**: カメラを閉じずに次々と撮影・登録できる（初回の大量登録の負担を下げるため。成功指標「100冊を2時間以内」の前提）
- F1-4 写真ライブラリから既存の写真を選んで登録できる（OSの写真ピッカーを使用。ライブラリ全体へのアクセス権は要求しない）
- F1-8 **一度に登録できる冊数の上限は30冊**（2026-11-11 オーナー判断）。登録待ちの一覧に入れられるのは30冊まで
  - 連続撮影は30冊目を撮ったところで止める。シャッターを押せなくし、「一度に登録できるのは30冊までです。いったん登録してから続けてください」と出す。「完了」で登録待ちの一覧へ進む
  - 写真ライブラリの複数選択も、登録待ちの残り（30冊 − すでに入っている冊数）まで（写真ピッカーの選択数の上限を設定する）
  - 撮影画面・ライブラリの選択画面・登録待ちの一覧に「n / 30冊」を出し、上限に近いことがわかるようにする
  - 登録を終えると数は0に戻り、続けて次の30冊を登録できる（成功指標「100冊を2時間以内」はこの繰り返しで満たす）
- F1-5 登録先の棚を撮影前に選べる（デフォルトは直前に使った棚、なければ未分類）。直前に使った棚が買いたい本だった場合は、買いたい本以外で直前に使った棚（なければ未分類）（2026-11-10 オーナー判断）
- F1-6 登録の入口は2つ置く（2026-11-10 オーナー判断）。どちらも同じ登録の流れ（撮影／ライブラリ → 登録待ちの一覧 → 登録）に入り、違いは最初に選ばれる棚だけ
  - A: 閲覧画面の下部バー右端の「＋」ボタン（2026-11-10 配置変更、F6-8）。常に表示する。初期の棚は F1-5 に従う。本が0冊のときの空の画面からも同じ入口に入る
  - B: 棚表示で一番最後の本の次に出る空きスロット。タップするとその棚を登録先にして登録を始める

### F2. 題名（必須）
- F1-7 **初回チュートリアル（2026-11-10 オーナー判断）**: 初めて起動したとき、チュートリアルで最初の1冊の登録まで案内し、登録を必須にする（スキップしない）。これにより「本が0冊の閲覧画面」は通常の使い方では出ない。詳細な画面はデザインのタスク D1
- F2-1 ~~題名は任意。空欄のままでも登録・表示・並べ替えができる~~ → **題名は必須**（§10 で変更）。題名が空の本は登録を確定できない。OCR候補を初期値として入れ、ユーザーが確認・修正して確定する
- F2-2 登録後、端末内の文字認識で表紙から題名候補を抽出し、題名欄に候補として提示する。撮影・登録の操作はOCR完了を待たない（非同期）
- F2-3 ユーザーは候補を採用・修正・破棄できる。手入力も可能
- F2-4 OCRは日本語（縦書き・横書き）と英語を対象とする

### F3. 日付の自動記録（§10 で変更）
- F3-1 ~~撮影日時を「棚に加えた日」として自動記録する~~ → 本を登録した日時を**データ追加日**として自動記録する（撮影・ライブラリのどちらから登録しても同じ）
- F3-2 ~~写真の撮影日時メタデータを使う~~ → 使わない。**購入日**の初期値はデータ追加日と同じ日付にする
- F3-3 ~~「棚に加えた日」を後から修正できる~~ → **購入日**はユーザーが後から修正できる。データ追加日は修正できない
- F3-4 登録待ちの一覧で、本ごとに「購入済み」のチェックボックスを持つ（2026-11-10 オーナー判断）
  - チェックあり＝購入済み、チェックなし＝買いたい（買いたい本に表示される）（2026-11-10 整合修正）
  - 初期値は全冊チェックあり（購入済み）
  - 一覧の上部に「すべて選択」「すべて解除」を置き、一括で切り替えられる
  - 購入済みの本は購入日＝データ追加日の日付で登録する。「買いたい」の本は購入日を持たない（2026-11-10 整合修正）

### F4. 棚の管理
- F4-0 ジャンル（＝棚）の管理は設定画面で行う（2026-11-09 オーナー判断）。設定画面へは下部バーの「表示」メニューの一番下から入る（2026-11-10 配置変更、F6-8）
- F4-1 棚を作成・名前変更・削除できる。削除時、中の本は未分類に移る（本は消えない）
- F4-2 棚の並び順を指で並べ替えられる
- F4-3 1冊の本は1つの棚にのみ所属する（物理的な本棚の比喩に合わせる）

### F5. 棚の中の並べ替え（コア体験）
- F5-1 棚の中の並べ替え: 本を**長押しで選択し、左右にスワイプ**して位置を入れ替える（2026-11-09 オーナー判断）
- F5-1b 長押しで選択した本の操作は方向で分ける: ←→ 並べ替え／↑ 別の棚へ移動（棚選択シート）／↓ 削除（確認ダイアログ）
- F5-2 本を別の棚へ移動できる（ドラッグ操作またはメニューから）
- F5-3 棚の自動整列: 「手動（自分で並べた順）」「購入日（新しい順／古い順）」「データ追加日（新しい順／古い順）」「題名順」から選び、一括で整列できる。整列後も手で並べ替えを続けられる。~~入口は閲覧画面で題名が表示される行の右端のボタン（2026-11-09 オーナー判断）~~ → 入口は下部バーの「表示」メニューの「並べ順」（F6-8。題名横の並べ替えボタンは廃止）。購入月別では「並べ順」を出さない（F6-7）（2026-11-10 整合修正）

### F6. 本棚の表示（コア体験）
- F6-1 本棚画面で、各棚の本を書影の面陳で、本屋の棚のように並べて表示する。表紙は元の縦横比を保つ
- F6-2 棚一覧から棚を選んで、その棚の全冊を表示できる
- F6-3 本をタップすると詳細を表示する。詳細は**データの表示だけ**（2026-11-09 オーナー判断）: 大きな表紙・題名・ジャンル・所持状況・購入日（購入済みの本のみ。「買いたい」の本では表示しない（2026-11-10 整合修正））。**データ追加日は画面に表示しない**（内部データとして保持し、並べ替え「データ追加日順」にだけ使う）（2026-11-10 オーナー判断）
- F6-4 題名・購入日・ジャンル・所持状況の編集と表紙の撮り直しは、**個別の詳細ページ**で行う（2026-11-10 オーナー判断）。詳細ページ右上の「編集」で編集モードに切り替え、「完了」で保存、「キャンセル」で破棄する。データ追加日は表示も編集もしない。本の削除は、長押しで選択した後の**下スワイプ**で確認ダイアログを出して行う（2026-11-09 オーナー判断）
- F6-6 表示の切り替え（2026-11-09 オーナー判断）: 閲覧画面で「棚表示（面陳で並ぶ現在の表示）」と「グリッド表示（横3列のシンプルな一覧）」を切り替えられる
  - グリッド表示では、本を長押しするとメニューが出て、別の棚へ移動・削除を選べる。並べ替えは長押しからのドラッグで行う
  - グリッド表示では縦スクロールが一覧のスクロールになるため、棚の切り替えは左右スワイプで行う（2026-11-10 オーナー確定）
- F6-7 まとめ方の切り替え（2026-11-10 オーナー判断）: 閲覧画面で「ジャンル別（棚）」と「購入月別」を切り替えられる。切り替えは下部バーの「表示」メニューの「まとめ方」で行う（2026-11-10 配置変更、F6-8）
  - 購入月別: その月に購入した本を横に並べ（横スワイプで本をめくる）、縦スワイプで月を移動する。月の中の並びは購入日の古い順（1日 → 31日。カレンダーと同じ）（2026-11-10 オーナー判断）
  - 購入月別で**ピンチイン（指を閉じる）**すると月を年にまとめる（その年の本を横一列に並べ、縦スワイプで年を移動）。**ピンチアウト**で月に戻る。iPhoneの写真アプリと同じ向き（2026-11-10 オーナー判断）
  - 本が1冊もない月・年は飛ばす（ジャンル別の「本が入っているジャンルだけ」と同じ扱い）
  - 購入月別では、上部の月・年の名前（例「2026年10月」）に「▾」を付けず、押しても一覧は開かない。月・年の移動は縦スワイプだけで行う（2026-11-10 オーナー判断）
  - 購入月別の並びは購入日順で固定し、手での並べ替えはしない。「表示」メニューの「並べ順」も購入月別では出さない。本の詳細・別のジャンルへの移動・削除はできる（2026-11-10。「表示しなくていい」の判断に合わせた解釈）
- F6-8 閲覧画面の配置（2026-11-10 オーナー確定。上部の部品が多くシンプルさを損ねていたため、案2「操作を下に移す」に案3「棚の名前から棚一覧」を足した形を採用）
  - 上部: ボタンを置かない。棚の名前（例「哲学・思想 ▾」）と冊数だけ
  - 棚の名前をタップすると「棚を選ぶ」シートが開き、分類ごとに並んだ全ジャンル（システムの棚を含む）から選んで移動できる。縦スワイプでの棚の移動はそのまま残す
  - 棚を選ぶ部品は1種類のリスト（分類ごとの見出し・冊数つき）にそろえる。本の移動先を選ぶとき（長押し→上スワイプ）も同じリストを使う。移動先を選ぶときは本が0冊のジャンルも出す（2026-11-10 オーナー判断で統一。リストを採用）
  - 右端の棚インジケータ（点の列）は置かない（ジャンルが多いと並びきらないため、棚一覧で代える）
  - 下部バー: 左から「表示」・検索欄（題名・よみで検索）・「＋」の3つ
  - 「表示」メニューにまとめるもの: 見え方（棚／グリッド）、まとめ方（ジャンル別／購入月別）、この棚の並べ順、設定。これまでの上部の歯車・表示切り替え、題名横の並べ替えボタン、下部の「ジャンル別｜購入月別」は廃止
  - 操作のヒント（← → 本をめくる ↑ ↓ 棚をかえる 棚の名前をタップで一覧）は下部バーの上に残す
  - 「買いたい」の本は購入日を持たないため、購入月別には出ない（§10.3 で確定）（2026-11-10 整合修正）
  - 購入月別でもグリッド表示を使える（2026-11-10 オーナー判断）。グリッドでは月ごとの見出しを付けた1本の縦スクロールにし、スクロールで月を移動する（見出しは上に固定）。ピンチインで年ごとの見出し＋1行5冊の細かいグリッドに、ピンチアウトで月に戻る
  - ~~購入月別での並べ替え・別の棚への移動は未決~~ → F6-7 で確定: 並びは購入日順で固定し手での並べ替えはしない（「並べ順」も出さない）。本の詳細・別のジャンルへの移動・削除はできる。並びは購入日の古い順（2026-11-10 オーナー判断）
- F6-5 見た目・アニメーション・操作感の詳細はオーナーが作成する Figma デザインに従う
- F6-9 **100冊以上の棚では、位置の下にスクラバーを出す**（2026-11-11 オーナー判断）。なぞると上に行き先の表紙・題名・位置を出し、指を離すとその本へ移動する（Figma P-1・P-2）

## 6. セキュリティ・プライバシー要件
- S1 **外部通信ゼロ**: アプリは URLSession 等のネットワークAPIを使わない。通信する可能性のあるサードパーティSDK（解析・広告・クラッシュ収集等）を入れない
- S2 認証: アカウント・ログインなし。認証機能を持たない
- S3 秘密情報: APIキー・トークン等の秘密情報は存在しない（コード・設定に含めない）
- S4 権限は最小限: カメラ（撮影のため、用途説明文を設定）、写真ライブラリへの追加のみ（共有画像の保存のため）。ライブラリの読み取り権限は要求しない（F1-4はシステムの写真ピッカーで実現）
- S5 保存データの保護: OSのデータ保護（Data Protection）を有効にし、端末ロック中はデータを読めない状態にする
- S6 入力検証: 題名・棚名は長さの上限（例: 200文字）を設け、制御文字を除去する。画像はアプリ内で再エンコードしてから保存し、外部由来のメタデータ（位置情報等）を保存画像・共有画像に残さない
- S7 App Storeのプライバシー表示は「データの収集なし」とする
