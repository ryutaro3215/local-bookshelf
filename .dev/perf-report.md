# Perf report — T12（性能・アクセシビリティ・オフライン）

更新: 2026-11-19（dev-builder。§2 にサムネイル800px での再計測を追記）

## 1. 計測の条件

- 計測した環境: シミュレータ iPhone 17 Pro（iOS 26・ID 64DCF75A）、Mac は Apple M5、Xcode 27.2（27B52）、デバッグビルド
- **注意**: requirements N1 の基準機は「iPhone 13 相当」。シミュレータは Mac の CPU で動くため、実機の値ではない。実機での計測は下の「4. 実機で残っていること」（docs/notices.md N-090）
- データ: `-UITestPersistentStore -UITestReset -SeedPerf 500` で作った500冊（Bookshelf/Debug/SeedData.swift。デバッグビルドのみ）
  - 棚: 小説に200冊、残り300冊をほかの初期ジャンル27棚に均等に。1割（50冊）は「買いたい」
  - 購入日: 2025-01-01 から約2年に散らす
  - 表紙: 実際の登録と同じ CoverProcessor（台形補正・長辺1600px・JPEG 0.85・サムネイル長辺400px）を通した JPEG。オーナーの実写サンプル25枚（design/sample-covers/raw。git 管理外）を順に使った。実写はシミュレータの一時フォルダにだけ保存し、リポジトリには入れていない
- 実行: `xcodebuild test -project Bookshelf.xcodeproj -scheme Bookshelf -destination "platform=iOS Simulator,id=64DCF75A-D3DE-4660-85D9-2CB8684A2F40" -only-testing:BookshelfUITests/PerformanceTests`（5件・約86秒。結果は「PERF」で始まる行）

## 2. 結果（N1・N2）

| 項目 | 基準 | 結果（シミュレータ） | 判定 |
|---|---|---|---|
| コールドスタートから棚の表示まで | 1秒以内 | 中央値 **0.902 秒**（5回: 0.928 / 0.892 / 0.927 / 0.902 / 0.884） | 満たす（余裕は約0.1秒） |
| 起動の指標 XCTApplicationLaunchMetric（最初のフレーム・応答可能まで） | 記録 | 平均 0.938 秒（相対標準偏差 4.8%・5回） | 記録 |
| 棚のスクロール XCTOSSignpostMetric（横に本をめくる×3） | 記録（目に見えるフレーム落ちがない） | Scroll_DraggingAndDeceleration の所要時間 平均 0.594 秒（相対標準偏差 1.4%）。**ヒッチ率（hitch time ratio）はシミュレータでは出ない** | 実機で要計測 |
| 共有画像の生成（小説の棚＝200冊のモザイク） | 3秒以内 | 4:5 の縮小が出るまで **1.95 秒**、9:16 のプレビューが出るまで **2.19 秒**（共有マーク・共有先を押してから。シートの表示のアニメーションと表紙200冊の読み込みを含む） | 満たす |
| 500冊のデータ容量（データベース＋表紙のフォルダ） | 300MB 以下 | **138.3 MB**（138,301,440 バイト。1冊あたり約 277KB） | 満たす |

補足:
- 起動の計測は、アプリ自身がプロセスの開始時刻（sysctl の kinfo_proc）から、閲覧画面に本が出た次の描画までを測っている（`-PerfProbe` のときだけ。Bookshelf/Debug/SeedData.swift の PerfProbe）。dyld・アプリの初期化・SwiftData の読み込み・棚の表示を含む
- 共有画像の生成そのもの（表紙の読み込みと描画）は、ShareRendererTests の単独実行で 0.01〜0.08 秒（30冊まで）。200冊では UI 上で約2秒かかっており、シートの表示待ちと表紙200枚の読み込みが大半と見られる。実機（iPhone 13）では3秒に近づく可能性があるので、実機で確かめる
- データ容量は実写の表紙での値。表紙の写真によって1冊あたりの大きさは変わる（25枚の平均）

## 3. 最大の文字サイズ（N5・N7。docs/notices.md N-083）

`DynamicTypeUITests`（BookshelfUITests/DynamicTypeUITests.swift。4件）を、最大の文字サイズ（`-UIPreferredContentSizeCategoryName UICTContentSizeCategoryAccessibilityXXXL`）で日本語・英語それぞれ実行し、すべて通過した（2026-11-18）。

確かめていること:
- 主要画面の主な操作ボタンが画面の中にあって押せる（スクロールの中のものは、スクロールして全体が枠に入る）
  - 閲覧（Q-1）: 棚の名前・共有マーク・下部バーの表示・検索・＋
  - 表示メニュー（G-2）: 見え方・まとめ方・（スクロールして）設定
  - 設定（F-1）・ジャンル管理（F-2）: ジャンル管理・追加・編集
  - 詳細（Q-3）: 戻る・編集
  - 編集（E-6）: キャンセル・完了、ジャンル・所持状況・購入日の行
  - 検索（E-4）: 検索欄・キャンセル
  - 共有（K-2・K-4・K-3）: 共有先4つ・キャンセル、戻る・投稿・写真に保存、範囲（この日／この月）・次へ・キャンセル
  - 購入月別（J-1）: 月の見出し・共有マーク・下部バー
  - 登録（A-2・A-3・C-2）: 登録先・写真を撮る・ライブラリから選ぶ・キャンセル、閉じる・シャッター・ライブラリ・完了、登録待ちの閉じる・登録・追加の2つ・本の行の題名とチェック
  - チュートリアル（L-1・L-2・O-1）: 最初の1冊を登録する、棚の行・この棚で撮影する、カメラを許可する・写真ライブラリから選ぶ
- 編集画面: 「キャンセル」「完了」「本を編集」が互いに重ならない。ジャンル・所持状況・購入日の行が重ならない（「買いたい」に切り替えた後も）。所持状況の切り替えは縦に並び、2つとも画面の幅の6割より広い（固定幅76で「O…」「W…」に省略されていた形をやめた）
- 共有のプレビューの見出しと「戻る」、登録待ちの見出しと「閉じる」が重ならない

直したこと（直す前は T12 の調査で全画面のスクリーンショットを撮って確認）:
- 閲覧画面（購入月別を含む）: 中の表示を縮めて切り、下部バーと案内を必ず画面に残す。閲覧画面の文字の拡大は AX2（アクセシビリティの2段目）までにした（表紙の大きさが決まっているため。シート・詳細・編集・設定などは上限なし）。案内の文（読み上げ対象外）は xxxLarge までで1行
- 編集: 大きい文字では上の行を2段（キャンセル｜完了の下に見出し）、カードの行は項目名を値の上に置き、所持状況は縦並び・幅いっぱい
- 表示メニュー: 大きい文字では画面の幅に広げ、項目を折り返し、入らなければスクロール
- 登録方法のシート: 大きい文字では画面いっぱいに広げてスクロール。行の高さを固定しない
- 登録待ち: 大きい文字では上の行を2段に、追加ボタンを縦に、購入済みの見出しと選択ボタンを2段に、追加ボタンなどを一覧と一緒にスクロール。本の行はチェックと表紙の下に題名・ジャンル・状態を幅いっぱいに。題名の欄に「必須」を重ねない
- 共有: 範囲を選ぶシートは大きい文字では画面いっぱいでスクロール、範囲の名前の下に補足。共有先は1行ずつ。プレビューは「戻る」の下に見出し
- チュートリアル: 主ボタンは2行まで折り返す。絵と文の部分（L-2 は見出しも）をスクロールにして、ボタンを画面に残す
